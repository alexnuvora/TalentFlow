# Engineering review — 16 September 2026

This release is a hardening pass, not a certification of production readiness or UK legal compliance.

## Implemented

- AI_BASE_URL, AI_API_KEY and AI_MODEL configure an OpenAI-compatible Chat Completions provider. Base URL includes the API version (for example https://api.openai.com/v1); the function appends /chat/completions. HTTPS is required. OPENAI_API_KEY / OPENAI_MODEL remain legacy fallbacks. Model selection is explicit, not hard-coded.
- Staff authorisation and matching application/job/candidate checks occur before any AI request. Provider errors are redacted; requests have a timeout and reject redirects. Reports are validated and storage errors checked. AI no longer overwrites candidate scores or recruiter summaries.
- Existing candidates cannot obtain a portal token or overwrite an existing CV just by submitting an email address. Repeat applications currently require recruiter-assisted identity verification; self-service verified-email access remains to be built.
- Booking checks the candidate's company and correctly supplies candidate_id when creating the interview.
- Tenant defaults repair insert flows that omit company_id. Composite foreign keys prevent cross-company references. Campaign creation handles optional UUIDs and a default source.
- Raw candidate/application/interview/commercial/submission records are staff-only. Client portal uses an allowlisted response containing only explicitly submitted candidates and related interviews. Client review RPC checks company, role and non-draft status. Portal token generation is staff-only.
- Optional campaign analytics disabled pending an explicit consent mechanism. Activity logs cannot be updated/deleted through the authenticated Data API (database administrators retain access).

## Environment and deployment

Vercel builds the Vite frontend. Configure VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY (a publishable key is also accepted). These values are public. Configure the legal company name, address and privacy email before launch.

AI runs in **Supabase Edge Functions**. Set AI_BASE_URL, AI_API_KEY and AI_MODEL in Supabase project settings → Edge Functions → Secrets, or with `supabase secrets set --env-file <private-file> --project-ref mzkaodoruhklzluikagy`. Never commit the private file or put AI_API_KEY in a VITE_ variable. A non-OpenAI provider must implement the compatible `/chat/completions` response format.

Deploy both index.ts and provider.mjs for ai-screen-candidate, and redeploy submit-application. Apply migrations/20260916163323_review_hardening.sql **after V9**. Existing root SQL files are the historical bootstrap sequence; this migrations folder alone does not bootstrap an empty database.

Set PUBLIC_APP_URL in Supabase to the final Vercel/custom domain. Configure Supabase Auth site URL and allowed redirects for that domain. Create the first company and owner profile through a trusted administrative process; public signup must not grant staff privileges.

## Verified and remaining launch blockers

Local production build, six Node tests for AI configuration/output validation, and npm audit pass. No actual provider call, real notification delivery, authenticated browser journey or payment collection has been verified. The live database had zero companies, profiles and candidates during review.

Remaining work includes:

- Verified-email candidate access, atomic application/CV persistence and orphan-file cleanup; upload content inspection/malware scanning. The submission endpoint is still a multi-operation workflow, not one transaction.
- CV text extraction is NOT implemented. Screening uses qualification answers and cover note only. Human review workflow, fairness evaluation, AI provider processing agreement and transfer assessment remain necessary.
- Automation queue locking/idempotency, delivery receipts, suppression/opt-out enforcement and production scheduler configuration need end-to-end testing before enabling sequences. Stripe/Xero remain connection registries, not completed payment/accounting integrations.
- Commercial ledger still needs accounting-grade validation, fee-change history, real invoice issuance and reconciliation. Client decision buttons and complete follow-up workflows remain unfinished.
- UI still contains loosely typed legacy components and incomplete error handling. Many route-level operations need integration tests. Role-based navigation, vacancy-question editing and configuration UX require further work.
- Retention and data-rights fields are not automated erasure/export workflows. Privacy/terms templates require actual legal identity and review against business practices. No claim of complete UK compliance is made.

Do not use this deployment for real applicant data until these launch gates are resolved and an authenticated dummy-candidate journey has passed.
